# Real phone acceptance for the simpler exchange

Owner feedback on 23 October 2026: the previous experience did not make the
purpose or next action clear to the other person. The simplified candidate
needs a fresh trial with the same users. Automated checks are not that trial.

Give two people this task without coaching: “Save a check with each other so
that, on a future call, you can check you still have the same private words.”

| Trial | What to record |
| --- | --- |
| First use, iPhone and Android/GrapheneOS | Phone/OS/browser, time including protection prompts, any unclear screen, and whether both saved the intended person. |
| Two prepared phones, no network | Both open Connect and face screens together. Record front-camera focus, glare, distance, QR readability and whether both finish unaided within the one-minute target. Record the exact sticking point rather than coaching a pass. |
| Phone and desktop webcam | Record code alignment and readability in both directions, including a slower device. Both must obtain and compare their four words. |
| Desktop without camera | Show its code, transfer the phone public reply file using an actual offline method, open it, then read the updated desktop QR on the phone. Record which OS transfer works. |
| Camera pause and clock change | Pause beyond a minute, resume the same saved session and verify the comparison stays fixed. Setup must not expire or silently replace its peer. |
| Interrupt either phone during setup | Whether each can find and resume the same saved exchange, without a replacement pair or a false “both complete” claim. |
| Later call in WhatsApp/Signal/etc | Open Vouch, unlock, find the name and compare words; record app switching and actual biometric/PRF behaviour. |
| Wrong words and agreed duress | Whether the listener uses the correct private checker and follows the agreed human plan; Vouch sends no alert. |
| Cleared storage/new device | Restore a test encrypted backup or perform selected-pair copy. Check original contacts and credentials are preserved. |
| Understanding | Ask what a match means and whether it authorises an unusual request. It demonstrates secret/key continuity; it does not exclude a live relay or prove platform account ownership. |

Use dummy relationships and words for recordings. Do not retain real pair seeds,
unlock secrets, live words, or other people's private names in evidence.

My Signet native Android phone tapping is a separate device acceptance path. The
Vouch website uses automatic public-code commit/reveal exchange; it must not offer or claim a
browser NFC bump. No physical acceptance is recorded by this checklist itself.
